# TechHub — ключ для преподавателя (не публиковать студентам)

Демо-страница: `practicals/qa-bug-hunt/index.html`. Самодостаточный HTML/CSS/JS без бэкенда и внешних зависимостей — можно опубликовать как есть (например, через GitHub Pages, Netlify Drop или Claude Artifact) и раздать ссылку студентам.

Задание для студентов: пройти пользовательские сценарии (поиск → корзина → регистрация → вход → рассылка → обратная связь), найти дефекты и оформить их как тикеты в Jira (Summary, Steps to Reproduce, Expected/Actual, Severity, Priority).

Всего заложено **15 дефектов**: 2 Critical, 3 High, 5 Medium, 3 Low, 2 Trivial.

## Critical

1. **Вход не проверяет учётные данные.** Форма логина принимает вход при пустых или любых полях email/пароль — авторизация фактически отсутствует.
   *Как найти:* нажать «Войти», не заполняя поля → появляется «Вход выполнен успешно!».
   *Jira:* Security / Auth bypass, Critical.

2. **Регистрация не сверяет пароль и подтверждение пароля.** Поле «Подтвержение пароля» существует, но его значение никогда не сравнивается с паролем — форма отправляется успешно при любом расхождении.
   *Как найти:* ввести разные значения в «Пароль» и «Подтвержение пароля» → «Регистрация прошла успешно!».
   *Jira:* Data integrity, Critical.

## High

3. **Кнопка «Добавить в корзину» не работает для Powerbank.** Опечатка в обработчике (`addTocart` вместо `addToCart`) — клик ничего не делает, в консоли `ReferenceError`.
   *Как найти:* открыть DevTools → Console, кликнуть по кнопке у товара «Powerbank 10000 мАч».
   *Jira:* Functional / Broken core flow, High.

4. **Итоговая сумма корзины не учитывает количество.** При увеличении количества товара строка «Итого» не пересчитывается пропорционально — сумма всегда считается как будто qty = 1.
   *Как найти:* добавить товар, нажать «+» несколько раз, сравнить «Итого» с ожидаемой суммой (цена × количество).
   *Jira:* Calculation error, High.

5. **Валидация email при регистрации слишком слабая.** Регулярное выражение принимает адреса без домена верхнего уровня, например `user@test` или `weird@weird`.
   *Как найти:* ввести `weird@weird` в поле email при регистрации → форма проходит.
   *Jira:* Input validation, High.

## Medium

6. **Поиск по каталогу регистрозависим.** Запрос «чехол» (строчными) не находит товар «Чехол для смартфона Slim», хотя запрос «Чехол» с заглавной находит.
   *Как найти:* ввести в поиск «чехол» и «Чехол» — результаты отличаются.
   *Jira:* Usability / Search, Medium.

7. **Чекбокс «Запомнить меня» не кликается по тексту.** Подпись не является `<label>`, связанным с чекбоксом — клик по слову «Запомнить меня» не переключает чекбокс, работает только клик точно по квадрату.
   *Как найти:* кликнуть по тексту рядом с чекбоксом на форме входа.
   *Jira:* Accessibility/Usability, Medium.

8. **Подписка на рассылку принимает пустой/некорректный email.** Форма показывает «Спасибо за подписку!» независимо от содержимого поля.
   *Как найти:* оставить поле email пустым или ввести случайный текст и нажать «Подписаться».
   *Jira:* Input validation, Medium.

9. **Поле «Телефон» не валидирует ввод.** Принимает буквы и произвольные символы без ошибки.
   *Как найти:* ввести «abcdef» в поле телефона при регистрации и отправить форму.
   *Jira:* Input validation, Medium.

10. **Количество в корзине может уйти в 0 или отрицательное значение.** Кнопка «−» не останавливается на 1 (при qty=1 товар исчезает без предупреждения; сам счётчик не защищён от ухода в минус, если логику изменить/при гонке кликов).
    *Как найти:* добавить товар, нажимать «−» несколько раз подряд, наблюдать поведение количества.
    *Jira:* Boundary/Edge case, Medium.

## Low

11. **Иконка показа пароля не меняется.** При клике на 👁 тип поля переключается password/text корректно, но сама иконка всегда остаётся 👁 (должна меняться на 🙈 или аналог).
    *Как найти:* нажать на иконку глаза у поля пароля, поле раскрывается, но иконка не отражает состояние.
    *Jira:* UI/Cosmetic, Low.

12. **Опечатка в подписи поля.** «Подтвержение пароля» вместо «Подтверждение пароля» (форма регистрации).
    *Jira:* Copy/Typo, Low.

13. **Футер ломается на узких экранах.** Колонки футера заданы фиксированной шириной без переноса — на экране ~380px и уже колонки обрезаются/перекрываются.
    *Как найти:* сузить окно браузера до ширины смартфона (~375px) и прокрутить к футеру.
    *Jira:* Responsive layout, Low.

## Trivial

14. **Несогласованный стиль кнопок.** Кнопка «Отправить» в форме обратной связи оформлена отдельно от дизайн-системы (другой цвет, почти без скругления углов) в отличие от остальных primary-кнопок сайта.
    *Jira:* Visual consistency, Trivial.

15. **Год в копирайте футера устарел.** «© 2022 TechHub…» — год захардкожен и не совпадает с текущим.
    *Jira:* Cosmetic, Trivial.

---

## Как использовать на занятии

1. Опубликуйте `index.html` (например, как Claude Artifact, GitHub Pages или любой статический хостинг) и разошлите студентам ссылку.
2. Попросите студентов **не смотреть исходный код** до завершения ручного тестирования (изучение DOM/консоли — тоже валидная техника QA, но лучше зафиксировать это правило заранее).
3. Каждый найденный дефект студент оформляет отдельным тикетом в Jira с обязательными полями: Summary, Steps to Reproduce, Expected Result, Actual Result, Severity, Priority, окружение (браузер/разрешение экрана).
4. Для оценки сверяйте тикеты студентов с этим списком; засчитывайте и обоснованные находки сверх списка (значит, ключ можно дополнить).
