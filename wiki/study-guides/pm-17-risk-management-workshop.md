# Риск-мастерская (групповая работа, 30–40 минут)

Не часть основной ингест-схемы (raw → wiki → schema) — рабочий материал для очного занятия по теме «Управление рисками». Формат: 2–4 группы по 2–3 человека, каждая разбирает свой кейс (кейсы взяты из внешнего файла `Cases.pdf`, не входящего в `raw/`) через процесс PMBOK. Опирается на [[risk-management]] (RBS, реестр рисков, качественный анализ, пять стратегий реагирования) и [[contract-types]] (риски по типу контракта). Опубликовано как артефакт: https://claude.ai/code/artifact/3e57ef07-5326-4832-8181-0ddcde006118

## Ход работы

**Шаг 1. Идентификация (≈10 мин)**
Минимум 5 рисков по категориям RBS:
- Технические — требования, архитектура, технологии
- Управленческие — организация, коммуникации, ресурсы
- Коммерческие — договоры, подрядчики, клиент
- Внешние — законодательство, экономика, конкуренция

Формула для каждого риска: «если [причина] → то [риск-событие] → то [последствие]».

**Шаг 2. Анализ (≈10 мин)**
Расставить риски на матрице 3×3 (вероятность × воздействие: низкая/средняя/высокая). Выбрать топ-3 приоритетных риска.

**Шаг 3. Реагирование (≈10 мин)**
Для каждого из топ-3 рисков — одна из пяти стратегий (эскалация, уклонение, передача, снижение, принятие), обоснование и ответственный. Отдельно: как тип контракта кейса повлиял на выбор стратегии.

**Шаг 4. Защита (≈5–7 мин на группу)**
Три вопроса:
1. Какой риск главный — и почему именно он, а не другой из топ-3 (место в матрице)?
2. Что может «убить» проект целиком (не любой риск — тот, что срывает весь контракт/отношения с заказчиком)?
3. Как тип контракта кейса изменил выбор стратегии? (тот же риск в Fixed Price и в T&M потребовал бы разного ответа)

## Кейсы

Каждый кейс демонстрирует свой тип контракта из [[contract-types]] — специально подобрано так, чтобы студенты увидели на практике, как контракт определяет, на чьей стороне риск.

### Группа A — Consero (Fixed Price)
Организатор закрытых конференций для топ-менеджеров. Хочет заменить бумажные брошюры мобильным приложением с авторизацией, расписанием и личным маршрутом гостя.
- Контракт: Fixed Price · риски на исполнителе
- Оценка: 600 ч, срок фиксирован в контракте
- Технологии: iOS-приложение, сервер на Salesforce (чужая платформа заказчика), API строит backend-команда
- Затравка: зависимость от Salesforce-архитектуры, которую пишет не ваша команда, — и фиксированная цена. Что если API придёт с опозданием или не так, как ожидалось?

### Группа B — AF Gruppen (Fixed time / Fixed budget / Flex scope)
Строительный холдинг в Норвегии переводит HR, управление проектами и работу водителей/контролёров из Excel в единую ERP-систему.
- Контракт: FFF · риски делятся между клиентом и исполнителем
- Оценка: 12 000 ч, срок 8 месяцев
- Технологии: ERP на PHP + React, мобильные приложения iOS/Android для трёх ролей (Basic, Driver, Controller)
- Затравка: три независимых направления, четыре стейкхолдера с разными приоритетами, объём — единственный изменяемый параметр. Что урежете первым, если не успеваете?

### Группа C — Archery Game (Time & Materials)
Владелец розничной сети в Крыму запускает мобильную игру-шутер для продвижения бренда, с прицелом на PlayStation и Xbox.
- Контракт: T&M · риски на клиенте
- Оценка: 50 000 ч, первый релиз через 6 месяцев
- Технологии: Unity 3D (C#) для мультиплатформенной сборки; нужны геймдизайнер и 3D-модельеры — новых для команды роли
- Затравка: непрофильный заказчик выходит в новую для себя индустрию, огромный объём часов, команда с ролями, которых раньше не было в проекте.

### Кейс 4 (запасной) — Universal Pictures (Dedicated Team / Support SLA)
Поддержка и доработка Room Booking — приложения для бронирования гримёрок на съёмочной площадке, сделанного 2 года назад.
- Контракт: Dedicated Team (фактически support SLA) · минимальные резервы на риски
- Оценка: 1 000 ч, срок 6 месяцев, занятость команды 4 ч/день
- Технологии: легаси iOS-приложение (таргет — iOS 9), веб-панель, backend на PHP
- Затравка: старая кодовая база, частичная занятость команды, минимальные резервы по контракту. Что стареет быстрее — код или люди, которые его помнят?
