# PM 11 — Документирование требований: текстовые форматы, графические модели, стандарты

**Источники:**
- `raw/Lectures Summaries/pm_11_Requirements documentation.md`
- `raw/Slides/PM 11 Software requirements (Part 2).pptx.pdf`
- `raw/Transcriptions/Копия PM 11 Software requirements (Part 2).txt`

**Главная идея:** Документирование — не формальность, а инструмент, фиксирующий собранные требования в понятной, проверяемой и однозначной форме для всех участников проекта. Правильный выбор формы представления и соблюдение критериев качества требований напрямую снижает риски ошибок, переделок и конфликтов между стейкхолдерами.

---

## Ключевые темы лекции

### Три способа представления требований и графические модели
Текст, графические модели, формальные спецификации; зачем нужна визуализация (ограниченность человеческой памяти). Диаграмма потоков данных (DFD, нотации Gane & Sarson / Yourdon & Coad), диаграмма перехода состояний, диаграмма вариантов использования (extend), ER-диаграмма (типы связей), SwimLane и Value Added Diagram. Подробнее: [[requirements-modeling]].

### Стандарты документирования: SRS, ТЗ и Agile
SRS как отраслевой стандарт, ТЗ по ГОСТ 34 как договор заказчик-исполнитель, отличие классического подхода от работы с требованиями в Agile (эпики → user stories → backlog → MVP, Planning Poker, Definition of Done). Подробнее: [[srs-and-tz]].

### User Story, Use Case и Acceptance Criteria
Формат user story (as a role/I want/so that) и расширенный шаблон, acceptance criteria в форматах Gherkin (Given/When/Then) и Rule-Oriented, полный шаблон use case (правило «пинг-понга» действие-ответ). Подробнее: [[user-stories-and-use-cases]].

### Семь характеристик превосходных требований
Полнота, корректность, осуществимость, необходимость, приоритизация (MoSCoW, WSJF), непротиворечивость/недвусмысленность, проверяемость — с примерами плохих и хороших формулировок. Подробнее: [[requirements-quality]].

## Практические задания

7 заданий для очного занятия: построение DFD первого уровня для сервиса доставки еды; поиск и исправление трёх «плохих» требований HR SaaS-продукта по критериям качества; State Transition Diagram для статусов заказа e-commerce; user story с acceptance criteria в двух форматах (Gherkin и Rule-Oriented) для 2FA банковского приложения; SwimLane-диаграмма процесса согласования отпуска; приоритизация backlog MVP по MoSCoW для трекера привычек; заполнение шаблона Use Case для функции возврата товара.
