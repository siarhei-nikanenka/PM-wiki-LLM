# Project Schedule Management

Из [[pm-12-schedule-management]].

## Шесть процессов

**Группа планирования:**
1. **Plan Schedule Management** — политики, процедуры и методы разработки/контроля расписания (например, будет ли применяться метод критического пути); результат — часть общего плана управления проектом.
2. **Define Activities** — содержание проекта разбивается на конкретные, измеримые, реализуемые операции.
3. **Sequence Activities** — устанавливаются логические зависимости между задачами (см. ниже).
4. **Estimate Activity Durations** — сколько времени потребует каждая задача с учётом доступных ресурсов; методы: аналоговая, параметрическая, трёхточечная.
5. **Develop Schedule** — последовательность + длительность + ограничения ресурсов объединяются в итоговую модель расписания (диаграмма Ганта, метод критического пути, анализ «что если»).

**Группа мониторинга и контроля:**
6. **Control Schedule** — единственный процесс этой группы: фактические данные сравниваются с базовым расписанием, отклонения анализируются, план актуализируется. Расписание — инструмент не только контроля, но и коммуникации со стейкхолдерами.

Даже в Agile-командах, где точная дата не всегда критична, фиксированные сроки нужны для согласования с заказчиком, крупных вех и планирования ресурсов — поэтому подходы PMBOK 6 остаются актуальны.

## Определение зависимостей — три вопроса
Для каждой задачи: (1) что должно быть завершено до её начала (предшественники), (2) что выполняется параллельно, (3) что стартует сразу после неё (последователи). Основа для построения сетевой диаграммы.

## Сетевая диаграмма (PERT Network Diagram) и критический путь
Узлы — задачи, стрелки — зависимости. **Критический путь (Critical Path Method, CPM)** — самая длинная последовательность операций от начала до конца проекта; определяет минимально возможную длительность всего проекта. Любая задержка задачи на критическом пути напрямую сдвигает сроки проекта.

**Расчёт вперёд (Forward Pass):** от начала проекта вычисляются Earliest Start (ES) и Earliest Finish (EF) каждой задачи; ES первой задачи = 0, EF = ES + длительность; при слиянии путей берётся **максимальное** значение EF предшественников.

**Расчёт назад (Backward Pass):** от конца проекта вычисляются Latest Finish (LF) и Latest Start (LS); LF последней задачи = её EF, LS = LF − длительность; при расхождении путей берётся **минимальное** значение LS последователей.

**Временной резерв (Float/Slack)** = LF − EF (или LS − ES). У задач на критическом пути резерв всегда равен нулю. Положительный резерв даёт менеджеру гибкость — можно сдвинуть задачу или перебросить ресурсы на критические задачи без ущерба срокам.

**Чувствительность сети** — если несколько путей имеют одинаковую (максимальную) длительность, проект считается «чувствительным»: вероятность смены критического пути выше, требуется контроль сразу нескольких цепочек.

## Трёхточечная оценка (Three-Point Estimation)
Для каждой задачи: A (оптимистичная), B (пессимистичная), E (наиболее вероятная).
- Средневзвешенная PERT: **(A + 4×E + B) / 6** — используется чаще, весомее учитывает реалистичный сценарий.
- Треугольное распределение: **(A + B + E) / 3** — проще, при небольшом разбросе оценок.

Та же техника применяется к оценке стоимости в [[cost-management]] и к оценке задач в [[rfx]]/[[project-estimation]].

## Роадмэп и диаграмма Ганта
**Роадмэп** — максимально простое визуальное представление стратегии с крупными вехами; не заменяет детальный план (MS Project и т.п.), а упрощает коммуникацию со спонсорами. Форматы: по фазам, по временной шкале, по географии (rollout plan), нестандартные метафоры.

**Диаграмма Ганта** — стандарт де-факто: задачи как горизонтальные полосы на временной шкале, строится на основе критического пути; упрощает календарное планирование, визуализацию зависимостей, отслеживание прогресса.

## Сжатие сроков
- **Fast tracking** — параллельное вместо последовательного выполнение задач критического пути; сокращает срок, повышает риск ошибок и рассогласованности.
- **Crashing** — привлечение дополнительных ресурсов на задачи критического пути; сокращает срок, увеличивает затраты, не всегда повышает качество из-за издержек координации.

## Человеческий фактор в планировании
- **Закон Паркинсона** — работа заполняет отведённое время.
- **Синдром студента** — откладывание на последний момент.
- **Асимметрия оценок** — оптимизм на малых задачах, пессимизм на больших.
- **Закон Мёрфи** — неопределённость и непредвиденное.
- **Однозадачность людей** — нельзя эффективно работать над несколькими задачами одновременно.

Эти закономерности нужно учитывать при построении расписания, а не полагаться только на формальные расчёты.
